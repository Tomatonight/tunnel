# 分布式组网工具设计

只支持三层 IP 隧道：Linux 默认创建内核三层 net_device，其他平台默认使用 TUN；
所有虚拟网络共用该设备，可以给它配置多个 IP。
节点之间使用TCP控制连接，数据默认UDP，也可按peer选择TCP封装。TAP和以太网桥接不在当前范围。
Linux 也可明确选择 TUN 后端，此时不要求安装额外内核模块；Android 虽基于 Linux，默认仍为 VpnService/TUN。
程序需要支持 Linux、Windows、macOS 和 Android；协议、选路和加密逻辑与操作系统的
设备、socket 和事件通知接口分离。

当前已接通控制握手、路径同步、端到端握手和 TUN 数据转发。
Linux/WSL 与 Windows 已进行真实设备互通测试；macOS utun 后端、Android VpnService/JNI 工程已编写，
Target-platform builds and hardware validation are tracked in [development.md](development.md) and [Android README](../android/README.md).

## 配置示例

可选顶层字段 device_backend 为 "tun" 或 "kernel"。省略时按运行平台选择：Linux 默认 kernel，Windows/macOS/Android 默认 tun。
核心归一化和保存始终输出实际选择的 tun/kernel，显式 tun 不会被省略，配置复制到另一平台时保持原选择。
GUI 的“平台默认”仅在编辑时省略字段；导入未写该字段时保持“平台默认”，保存后按核心返回的有效后端显示。
kernel 仅适用于已加载 tunnel_kmod 的 Linux；不支持的平台或模块不可用时明确报错，不静默回退到 TUN。
Linux 内核后端的 UDP 数据在内核内封装、加解密和转发，TCP 数据继续经过用户态 TLS 通道。
配置、认证、地址分配、路径通告和会话协商仍在用户态，设备选择不改变 peer 的 UDP/TCP 协商方式。
每个实例独占一个 /dev/tunnel_kmod 控制 fd，通过 ioctl 下发完整状态及密钥，通过 read/write 交换事件和 TCP 密文记录。
关闭控制 fd 撤销该实例的网卡、UDP socket 和内核密钥；不使用全局共享控制设备状态或 Generic Netlink。
ndo_start_xmit 接管待发送包；缺少路由/密钥、资源不足、加密提交或发送失败时直接丢弃并计数，不等待发送条件恢复。
当前实现选择同步 Kernel Crypto API，在 xmit/接收路径完成处理，不等待异步密码队列；隧道层不增加重传队列。
原始命令行 --device-backend tun|kernel 可覆盖 JSON，整个进程的 watch/SIGHUP/config_apply 重载均保留覆盖。
不使用命令行覆盖时，界面或配置热加载可以切换 device_backend，切换会重建设备及连接。
内核模块需针对目标运行内核及其配置编译，兼容范围以实际构建和运行测试为准，不承诺所有 Linux/WSL 内核。

```json
{
  "address": "100.0.0.1:65535",
  "networks": ["10.1.0.2/24"],
  "peers": [
    {
      "address": "100.0.0.2:65535",
      "shared_key": "use-a-random-high-entropy-secret"
    }
  ]
}
```

peers[].address是对端的公网公布地址，TCP控制连接和UDP/TCP数据隧道都使用这个IP和端口号。
UDP模式使用独立UDP socket；TCP模式的数据复用已经认证的TCP/TLS连接。
顶层 networks 是本机虚拟 IP/前缀列表，每个网络只配置一次；不是对端地址。
上例中的 10.1.0.2/24 同时指定本机 IP 10.1.0.2 和虚拟网段 10.1.0.0/24。
解析时分别保留主机 IP 和规范化网段，不能在归一化 CIDR 时丢失主机位。
单网络时可以省略 peers[].networks；多网络时必须显式指定允许的网段，例如：
    "networks": ["10.1.0.0/24"]
引用只能是顶层已定义的子网地址，不能用带主机位的地址或未知网段。peer 的空列表不允许。
增加第二个网络后，原先省略授权列表的配置报错，不能自动给已有 peer 开放新网络。
peers 可省略，表示没有允许连接的对端；只有填入 peers 的节点才能认证接入。

顶层 address 是本机对外公布的公网 IP 和服务端口，同时作为本机节点身份。
不能把 0.0.0.0 或 :: 这样的通配地址作为公布地址。
可选的 listen.bind_address 表示实际本地绑定地址；省略时使用公布地址所属地址族的
本地通配地址和相同端口号。TCP 监听和全局 UDP socket 使用同一个本地绑定端点。
本机位于 NAT 后时，公布地址可能不在本机网卡上，实际绑定地址与公布地址应分开；
UDP模式需保证公布的TCP和UDP端点均可达；TCP模式仅要求TCP连接可建立，仍不实现NAT穿透。

listen 是可选高级设置对象；listen.enabled 默认 true，控制是否接受入站 TCP 控制连接。
主动连接由 peers 配置决定。listen.networks 省略时允许全部本机虚拟网络，显式 [] 禁止被动连接加入任何网络。
listen.networks 是被动接收连接的额外网络上限，实际仍需与对应 peer 授权和远端网络取交集。
即使关闭TCP入站监听，仍需配置本机公布地址；仍创建一个公共UDP socket，TCP模式的peer不使用它发送数据或探测。
tun_mtu/transport_mtu 默认 1280/1500，普通配置可以省略。

仍兼容旧 listen.address、每项 {tunnel,tunnel_ip} 的格式；不允许新旧字段混用。
旧格式先按原规则完整校验，再转换成同一个内部 Configure，保留原监听开关、绑定及所有授权子集。
serialize_config 输出新格式，省略可安全推导的默认值；tunnel --normalize-config 可校验并输出新 JSON。
device_backend 始终写出有效值，避免跨平台默认值不同而改变已有设备选择。
界面读取或导入只在内存转换，显式保存/连接时才写入新格式。无效配置保留原文供修正，不丢弃未知字段。

## 虚拟网络与配置校验

### 可选地址分配服务

本机可继续通过 networks 配置静态 host CIDR，也可通过 address_clients 向公网服务申请地址。
address_clients 每项配置服务公布 address、连接该服务所需的 shared_key，以及申请的子网 networks。
这些子网同时加入本机网络授权集合；同一网段不能同时静态配置或向多个服务申请，仍不支持网段重叠。
只有一个本机网络时 peer 可省略网络列表；混合静态和受管网络时仍需显式授权。

address_server 开启独立 TCP 地址分配服务，可单独运行，也可与普通节点共用一个事件循环。
与节点一起运行时，本机静态网络不能和服务的地址池重叠；本机通过 address_clients 向自己的服务申请地址。
纯服务配置只有 address_server，不创建 TUN 或 UDP socket。内嵌服务使用独立于 overlay 的 TCP 端点。
服务 networks 为各个独立 IPv4/IPv6 地址池。简单模式在 address_server 配置一把 shared_key，
不配置 clients；任何使用相同 PSK 通过认证的节点都可申请服务端配置的地址池，客户端 networks 选择申请子集。
新增节点不需要修改服务端配置；服务端仍自动维护运行连接和持久租约，以防地址冲突并支持重连保址。
保留旧 clients 模式：按节点公布地址配置独立 PSK 和允许的网络列表，服务端名单决定授权范围。
两种模式互斥，连 clients:[] 也不能与 shared_key 混用；加载或保存旧配置不自动改成共享模式。
地址服务 PSK 与 peer 间原有 PSK 分开使用；共同持有服务密钥不自动建立 peer 连接或扩大 peer 网络权限。
TLS PSK 身份绑定 allocation-v1 用途、客户端和服务公布地址，不能跨用途或换端点复用握手。
共享 PSK 只认证持钥组成员，不能证明某个节点独占所声明的公网地址；成员可冒用其他节点或服务端。
重复的在线节点身份仍被拒绝，但不能阻止持钥者先占用一个尚未在线的身份或申请多个身份耗尽地址池。
共享模式适用于本设计中彼此信任的接入节点；单独撤销成员需要为其余成员更换接入密钥。
需要独立撤销和更强身份约束时可继续用 clients 模式；以后可考虑服务端证书认证和接入码注册后签发独立节点凭据。
共享 PSK 的身份边界参考 RFC 9257 §4.1：https://www.rfc-editor.org/rfc/rfc9257.html#section-4.1。

客户端先完成 TLS 认证，再申请地址。每 5 秒保活和刷新授权，20 秒未收到合法活动则失效；
TCP 显式关闭或错误立即处理，失效后自动重连。首次分配前不配置占位 IP、不公布该网络可达性。
同一连接可请求多个池；一个池耗尽时报告该池错误，其余成功的池可独立启用。
地址按（网段、节点公布地址）绑定。server 将绑定原子落盘并锁住状态文件，避免两个进程同时分配。
状态文件不可读、损坏、被锁定或不能可靠保存时拒绝继续分配，不将已有文件当作空数据库。
普通重连或重启优先恢复仍保留的地址；已回收并重新分配的地址不能由旧节点缓存自行启用。

reclaim_after 是服务确认节点离线后等待回收的秒数，默认 86400（24 小时），可配置。
有效地址另附服务签名的短期凭据，绑定服务、节点、网段、IP 和到期时间；默认有效 60 秒。
签名公钥从已认证的服务 TLS 连接获得，每次服务进程启动使用新的签名身份；它不替代接入 PSK。
地址回收还须晚于已签发凭据到期并留 5 秒保护时间，因此很短的 reclaim_after 不会导致过早复用。
凭据时间使用系统时钟，节点与服务应保持时钟同步；过期或明显超出有效期的凭据被拒绝。

peer 的 Hello 协商双方允许的网络、手动/受管模式和对应服务身份。
受管网络必须双方启用同一服务，且相互验证该服务为对方签发的地址凭据；单方手动配置不能绕过。
控制连接支持 membership 更新，其加密上下文绑定协商的网络和服务集合；运行期间只能在该集合内启停。
服务失联时停止该网络收发和中转、移除本机该地址、撤回本机及经本机公布的该网路径、
停用该网端到端会话。共用 peer 的其他有效网络、身份公钥引用和会话继续保留；
没有剩余有效网络时关闭整条 peer 连接。重新取得有效地址后自动更新接口并恢复网络成员资格。
接口更新失败且设备已不可用时撤回全部 overlay 网络并显示错误，需断开后重新连接；地址服务可继续运行。

state_file 默认 address-leases.json：命令行相对配置文件目录解析，桌面界面相对私有配置目录解析，
Android 保存到应用私有地址状态目录。正常配置保存/校验不写或重置分配数据库。
示例见 examples/address-server.json、examples/address-client.json。
服务界面默认配置共享接入密钥，并可填写目标节点公布地址导出客户端配置；该地址不写入服务端名单。
旧逐节点模式继续支持授权节点管理；客户端导入时明确选择合并或替换。

### 基本规则

Tunnel 是一个虚拟网络的抽象，不单独创建 TUN 设备。
一个 Peer 可以关联多个 Tunnel，一个 Tunnel 可以关联多个 Peer。
Peer 和 Tunnel 可以使用哈希表存储。

Tunnel 的 key 为规范化后的网络地址和前缀长度。
同一 CIDR 在不同配置项中出现时引用同一个 Tunnel，不重复创建对象。
不同虚拟网络不支持重叠网段，例如 10.0.0.0/8 与 10.1.0.0/24 不能同时配置。

读取配置时检查 IP、端口、CIDR、MTU 以及必需字段是否合法，
检查 tunnel_ip 属于对应网段、同一虚拟网络的本机地址一致，
并检查所有不同虚拟网络之间不存在地址范围重叠。
配置上限为 1 MiB、16 层 JSON、256 个 peer、全进程合计 64 个不同虚拟网络。

## 线程与 UDP socket

用户态协议核心采用单线程模型，只有一个 event loop。以下收发模型适用于 TUN 后端。
TCP 控制/数据连接、UDP 收发、TUN 数据处理、加解密、选路和定时器均由该线程执行。
不创建 worker 池，不使用跨线程任务队列或共享状态锁。
thread_num 不再是可调参数；为兼容旧示例，仅接受省略或数值 1，其他值报错。

整个进程共用一个 UDP socket，选择 UDP 封装的 peer 使用这个公共数据收发入口。
Peer 不私有 UDP fd。
全局 UDP socket 绑定 listen.bind_address，并向各个 peer 的公布地址发送数据。
不需要协商额外的 UDP 端口。

event loop 负责 UDP 非阻塞收发，根据会话标识定位 peer 后直接处理报文。
发送暂时不可写时保留报文及下一跳地址，进入有界队列并等待可写事件。
队列满时丢弃新报文；每次回调限制收发批量，避免长期占用线程而饿死控制连接和定时器。
socket 的事件注册和生命周期统一管理，不在多个 event loop 上重复注册。

Peer 保存对端公布地址、链路会话和活性状态。
接收端先按会话标识定位候选 peer，再验证报文；认证通过前不能信任转发头或改变可达状态。
同一会话的序号和防重放状态由所属会话在该线程内管理。
操作系统的 socket 句柄类型通过适配层封装，Windows 不假定 socket 是 POSIX int fd。

kernel 后端保留用户态单事件循环，但 UDP socket、IP 数据处理及数据会话序号/防重放状态均由内核独占。
内核 xmit/接收可在不同 CPU 执行，每实例锁保护会话状态；用户态只发布原子配置快照和处理控制事件。
TCP 数据只在控制 fd 与用户态 TLS 之间交换逐跳密文；不会在两个位置同时更新同一数据会话的 nonce。
内核无法发送即丢弃，TCP 密文事件队列有界，不沿用 TUN 后端的 UDP 可写等待队列。

### 可选 TCP 数据封装

每个 peer 可配置 transport:"udp" 或 transport:"tcp"，默认 udp；同一节点可连接不同封装的 peer。
TCP 数据复用该 peer 已经建立的 TLS 控制连接，仍连接同一个公布 address，不增加监听端口或数据连接。
双方经过 PSK 认证后在 Hello 中声明 tcp_data:true 能力和本地 transport 偏好。
任一端选择 tcp 且双方支持时使用 TCP；双方均为 udp 时使用 UDP，不在运行中自动降级或回退。
旧版 Hello 缺少这些字段时视为仅支持 UDP；请求 TCP 而对端不支持时明确拒绝连接。
因此只需在一侧选择 TCP，但两端程序都需要支持该功能。热修改 transport 会仅重连受影响邻接。

控制帧保持原有4字节大端长度和JSON内容；长度最高位为1时表示二进制数据帧，低31位为长度。
数据帧装入完整的原链路AEAD记录，单帧非空且不超过65536字节；实际发送仍受现有MTU预算限制。
解析器支持拆包/粘包及控制与数据交错；只有协商TCP模式的连接接受二进制数据。
TCP模式链路exporter上下文额外绑定transport:tcp:v1；默认UDP上下文保持旧版兼容。
单播继续端到端加密，广播/组播继续逐跳保护；转发时按下一跳各自的封装发送，可跨TCP/UDP中转。
身份、网络授权、ECMP、RPF与内网发布权限不随封装改变。

TCP批量数据在发送队列达到512KiB前丢弃新整包，给控制/探测留空间；总输出硬上限1MiB。
已排队帧不会截断；接收缓冲和单次读取也受上限约束，所有操作仍在唯一协议线程执行。
状态peers[].transport显示当前协商结果，configured_transport显示本地设置；未连接时transport显示设置值。
tcp_data_sent/received与udp_data_sent/received统计链路记录（包含探测），tcp_data_send_drop统计拥塞丢包。
TCP适合UDP不通的链路；内层TCP叠加外层TCP可能因重传和队头阻塞降低吞吐，不承诺比UDP更快。
示例见examples/tcp-node-a.json、examples/tcp-node-b.json。

## 节点身份

公网 IP 加固定服务端口作为节点身份，也作为 Peer 的哈希 key。
每个节点需要有唯一且稳定的对外公布地址；地址改变视为节点身份改变。
这里的端口是节点公布的固定服务端口，不是主动 TCP 连接的临时源端口。
有 NAT 时需要显式确定映射后的公网地址和固定端口，不能简单使用本地监听地址。

本机公布地址取自顶层 address，在经过 PSK 认证的控制握手中传递。
不根据主动 TCP 连接的临时源端口推断节点身份。
节点地址只是标识，不能代替基于预共享密钥的认证。
需要区分直连 Peer 对象和可经其他 peer 到达的节点信息；直连失效不等于目标节点消失。

## 认证与加密

shared_key 是预共享密钥，按 peer 配置；每对直接连接的节点需要配置相同的密钥。
例如 A 为 B 配置的密钥必须与 B 为 A 配置的密钥一致，才能完成认证并建立可用会话。
不同 peer 关系可以使用不同密钥，不要求整个虚拟网络共享一把密钥。
密钥需要事先在两端配置；两端各自随机生成不同密钥无法互相认证。

入站连接根据握手中声明的节点公布地址，在已配置的 peers 中定位预共享密钥，
再验证握手；未知节点或验证失败的节点不建立可用 peer。
不能仅凭声明的地址就认为认证通过。

用户态加解密使用 OpenSSL，密码运算使用 EVP 高层接口。
在 CPU、OpenSSL 构建及所用 provider 支持时，由库自动选择硬件加速实现，
例如 x86 的 AES-NI、ARM 的 AES/PMULL 指令；没有对应硬件能力时使用软件实现。
用户态加解密在唯一的协议线程内调用，不依赖 OpenSSL 自动并行。
发送与接收使用独立的 EVP_CIPHER_CTX；同一密钥下保证 nonce 不重复，认证成功后才更新防重放窗口。
kernel 后端的数据 AEAD 使用同步 Kernel Crypto API 的 gcm(aes)，由内核选择可用加速实现；控制握手与会话协商仍使用 OpenSSL。
数据记录使用 AES-256-GCM，16 字节认证标签；通过 HKDF-SHA256 区分方向和通道用途。
相邻控制连接使用 OpenSSL TLS 1.3 外部 PSK 握手，PSK 输入为 SHA256(shared_key 的 UTF-8 字节)。
固定 TLS_AES_128_GCM_SHA256，密钥交换组为 X25519/P-256；禁用 0-RTT、票据及会话缓存。
PSK 身份字符串绑定主动端和接收端的公布地址，TLS 完成后还须交换版本 1 的 Hello 并通过所选数据通道的双向探测。
端到端握手同样使用 TLS 1.3，双方使用 Ed25519 身份私钥签署的证书，
校验器精确匹配从可信路径通告得到的原始公钥，TLS CertificateVerify 验证私钥持有关系；不使用 CA 信任链。
链路和端到端数据密钥经 TLS exporter 导出，再用 HKDF 派生两个方向；不直接把 PSK 用作业务密钥。
exporter 上下文包含节点身份、通道用途、授权网络；链路还绑定双方公钥，端到端还绑定随机握手标识。
端到端握手在路径收敛期间无进展时，以新随机标识和递增尝试序号重新协商，保留有界待发包及原总超时。
相同身份密钥下的迟到旧尝试不覆盖当前会话；重试不会向同一 TLS 状态重复注入旧记录。
完整上下文进入 exporter，其 SHA256 摘要进入后续 HKDF，以支持全部 64 个网络。
硬件能力差异不改变双方使用的算法。

节点身份公私钥在程序初始化时生成，
本次进程运行期间保持不变；TCP/UDP 临时断线和重连不重新生成这对身份密钥。
进程重启时生成新的身份密钥，通过重新建立的连接发布新公钥。
节点自身的私钥不会随某个 peer 断开而删除；配置的 PSK 也不会因重连或重启自动改变。
身份公私钥与会话密钥分开：新建连接重新握手并派生新的会话密钥，
不能在重置加密序号后复用旧的会话密钥和 nonce。

信任所有获准接入的节点如实转发节点身份、公钥和路径信息。
PSK 保护相邻 peer 的握手和控制通道，节点公钥随可达信息在虚拟网络内传播。
本方案信任这些转发节点提供的公钥绑定，不额外要求 CA 或预置每个远端节点的公钥指纹。
具体认证密钥交换使用成熟机制，握手必须绑定双方节点身份、用途和必要的虚拟网络信息。

控制连接和相邻数据链路保持逐跳保护，单播业务 IP 包另外采用端到端加密。
以 A 通过 B 向 C 发送单播数据为例：
1. A、C 从可信的可达通告中获得对方的身份公钥，经中转路径完成端到端握手并派生会话密钥。
2. A 加密完整的原始 IP 包，再封装必要的转发信息，通过 A-B 链路会话发送。
3. B 验证并解开相邻链路的保护，读取转发头，选定下一跳；业务 IP 包仍是端到端密文。
4. B 使用 B-C 的链路会话重新保护报文，C 验证并解密端到端数据后写入 TUN。

控制通道、相邻链路数据通道和端到端会话分别管理密钥、方向、序号与防重放状态。
Peer 表示直连会话；EndToEndSession 按虚拟网络和最终通信节点管理，不依赖某一条固定路径。
某条下一跳路径消失但目标仍可达且公钥未变化时，可以保留端到端会话并改走其他路径。
目标公钥发生变化时，失效对应的旧端到端会话，并使用新公钥重新握手。
广播和组播当前继续使用逐跳保护；端到端组加密方式另行处理。

## 节点可达信息与转发

控制协议在虚拟网络内通告和撤回节点可达信息：目的节点公布地址、tunnel IP、
节点公钥及其标识、跳数和完整传递路径。表达的是“到达某个节点可以通过哪些 peer”。
接收端根据通告来源记录下一跳 peer；路径中的节点使用公布地址标识。
公钥标识可使用公钥指纹，用于识别密钥是否变化，不把指纹作为消息新旧的排序依据。
拒绝接收传递路径中包含本节点的候选路径，避免重新学习经自身绕回的路径。

按（虚拟网络、目的节点、发布 peer）分别保存候选路径和公钥引用。
后续消息可以覆盖该发布 peer 针对同一目的节点的旧记录；撤回消息清除此来源的记录。
其他 peer 发布的有效记录继续保留，不能因一个来源的撤回而清空整个目的节点。
同一目的节点存在多份公钥通告时，按当前仍有效记录中本地最后处理的公钥通告更新缓存。
撤回该记录后根据剩余有效记录重新计算；在所有相关虚拟网络中都无有效路径时，
才删除该节点的学习记录和公钥缓存。在某个虚拟网络内已不可达时，立即停用该网络的端到端会话。

同一 TCP 控制会话内有顺序，多个 peer 的不同 TCP 会话之间没有全局消息顺序。
本版按本地接收处理顺序覆盖，不增加用于比较节点启动新旧的全局版本协议。
节点重启导致原邻接断开并触发撤回，但不同路径上的撤回和新通告可能交错到达；
不假定所有节点都会先处理完旧记录撤回，再收到新公钥。
收敛期间可能暂时覆盖为旧公钥；密钥不匹配时丢弃数据或等待重新握手，不降级为明文。
连接重建后重新同步可达信息；旧连接已经失效，其排队任务不得覆盖新连接的记录。

单播采用 ECMP：按跳数比较代价，保留多个不同下一跳的最短有效路径，
按流选择下一跳，同一流在候选集合不变时保持选路稳定。
同一 peer 的多条路径不应使该 peer 在 ECMP 集合中被重复计权。
失效时删除对应候选并重算，仍有其他有效路径时继续转发，较长路径可作为备选。

源节点从内层 IP 流生成稳定的 flow_id；端到端加密后，中继使用外层 flow_id 进行选路，
不依赖读取内层端口。flow_id 使用固定 FNV-1a 64 位算法，对 IP 版本、源/目的地址和传输协议编号计算；
非分片 TCP/UDP 再加入源/目的端口。分片不加入端口，使首片和后续片使用同一流归属。
单播从 TUN 读出后确定虚拟网络和目的节点，建立或复用端到端会话，
加密并选择 ECMP 下一跳，再按该邻接协商的 TCP 或 UDP 封装发出。
中转节点必须加入同一个虚拟网络，且入站、出站 peer 关系都已获准承载该虚拟网络；
节点可达信息和数据的转发范围都限制在该虚拟网络内。

转发信息位于端到端密文外、相邻链路保护之内，至少包含虚拟网络、源节点、
目的节点或广播/组播类型、flow_id 和 hop_limit。
不可变的虚拟网络及端点、流标识与端到端会话绑定并受到端到端认证；
hop_limit 由中继递减，使用逐跳保护，不纳入不可变的端到端认证字段。
最终接收端解密后核对内层源、目的 IP 与虚拟网络及节点映射是否一致。
各跳转发都必须受 hop_limit 限制，防止收敛期间的临时环路无限转发。

## 子网路由分发与内核 SNAT

已确定的需求：
节点可将本机可达的内网前缀发布到其所属 tunnel。例如节点的 tunnel IP 为 10.1.1.1/16，
将内网 10.2.0.0/16 发布到 10.1.0.0/16，供这个 tunnel 的其他节点访问。
前缀绑定发布节点；数据先通过现有节点路径到达发布者，再由发布者转发到内网。
隧道的端到端加密终止于发布节点；发布者到内网设备的一段由内网及应用自身保护。

发布者可以选择是否启用出口 SNAT。修改源 IP 称为 SNAT；DNAT 修改目的 IP。
采用系统 NAT，由系统维护连接跟踪、地址/端口映射和回包的反向转换，不自建用户态 NAT 表。
启用时，内网设备看到发布者的内网出口地址；该地址在内网可达时，通常无需额外添加到 tunnel 网段的回程路由。
源地址不写死：Linux 使用 MASQUERADE，由目的路由确定出接口，再由内核选择该接口的源地址。
多个接口地址时不保证选择用户指定的某一个；当前没有 snat_address 字段。
一个发布前缀应使用同一物理出口；规则绑定配置时探测到的出接口，宿主改变出口路由后应断开重连以刷新规则。
关闭时保留原始源地址，内网仍需有相应回程路径，即使内网设备仅响应请求也不例外。
系统 NAT 和转发配置由各平台后端分别适配，不能仅凭存在 TUN 接口就认定出口功能可用。
第一阶段桌面平台作为内网出口，Android 作为访问端。
同一前缀由多个节点发布时，选择一个出口，其余备用；同一出口的中间路径继续使用现有 ECMP。
切换出口不共享 NAT 状态，已有连接通常需要重新建立，不能保证无缝迁移。

系统 NAT 的数据路径：
去程：隧道解密后保留原始 IP 包写入 TUN，由内核转发，并在出口执行 SNAT。
回程：内核先根据连接跟踪恢复原虚拟目的地址，再路由到 TUN，由程序读取、加密并返回源节点。
kernel 后端由自定义 net_device 接收解密后的包、在 xmit 处理回包，系统转发及 SNAT 规则不变。
仅在用户态改成发布者内网 IP 后写 TUN，不会让回包自动经过用户态映射表。

配置与实现：
发布节点在顶层配置 advertise_routes，访问端不需要手写这些内网路由。例如：
"advertise_routes": [
  { "tunnel": "10.1.0.0/16", "prefix": "10.2.0.0/16", "snat": true }
]
tunnel 是本机已加入的规范网段，可引用静态或地址服务管理的网络；prefix 必须是规范内网前缀。
snat 默认 false；省略整个 advertise_routes 则保持原有仅节点互通行为。每台最多发布 64 条。
禁止默认路由、与任何本机 tunnel 重叠的前缀，以及本机重复或部分重叠的发布。
复用既有节点通告和撤回，增加“所属 tunnel、发布前缀、发布节点”的映射。
发布者仍可经其他路径到达时保留其前缀；撤销发布、退出所属 tunnel 或完全不可达时撤回。
受管 tunnel 失去分配资格时同步停止发布和转发，不能影响其他 tunnel。
导入路由是单独的系统路由，不把发布前缀配置成新的 TUN 本机地址；发布者自身保留内网出口路由。
单 TUN 多地址时须保持导入路由与源 tunnel 的一致性；跨 tunnel 重叠的外部前缀应拒绝，避免选路歧义。
接收端仍校验源节点身份，仅允许其 tunnel IP 或其有效发布前缀作为来源，不能取消源地址校验。
Linux/macOS NAT 规则只覆盖授权 tunnel 访问对应前缀的流量，并绑定预期出接口。
Windows WinNAT 按内部 tunnel 前缀建立 NAT，数据面另限制只向有效发布前缀转发；
Windows 同一 tunnel 不允许同时配置 snat=true 和 snat=false 的出口，也不允许多个 SNAT tunnel。
只有转发、过滤及所需 NAT 后端准备成功才公布可用出口；退出时只清理本程序拥有的路由及 NAT/过滤规则。
同一 tunnel 完全相同的前缀支持主备，按到发布者的最短跳数、节点地址依次选择。
同一 tunnel 不同长度的重叠前缀、不同 tunnel 的重叠前缀，均标为冲突而不安装；普通节点路径保留。
通告保留冲突声明，以免双方反复撤回又重新发布；冲突消失后恢复。导入还检查本机已有路由与传输端点。
每条流在发布者仍可达时保持原出口；出口失效后新流选择备用，已有连接可能失效。

访问方向已确定：本次只支持隧道节点主动访问发布的内网，不开放内网设备主动发起的新连接，
也不扩展为两处内网设备之间主动互访。内网设备通过已有连接正常回包。
“仅响应”仍允许既有连接双向传输数据，例如节点打开内网页面后接收内容、上传文件、WebSocket 服务端推送。
系统有状态转发策略只允许获准请求对应的返回流量及必要的关联 ICMP 错误；
拒绝 LAN 向 TUN 发起的新连接，不自动启用 ALG 或笼统放行关联新连接。
UDP 的返回流量按系统连接跟踪的报文元组及超时识别，不按 TCP 长连接处理。
SNAT 开关不改变上述访问方向；不能把 SNAT 本身视为完整的访问控制。

核心额外保存有界的请求/回包对应关系，不做地址或端口转换。
当前内网访问支持 TCP、UDP、ICMP/ICMPv6 Echo，以及能关联到原请求的 ICMP 错误；其他 IP 协议暂不开放。
每个 tunnel 最多 1024 条记录；TCP/UDP/Echo 空闲超时分别为 7200/120/30 秒。
已识别首片后，30 秒内的同一 IP 数据报后续片可通过；乱序先到的非首片直接丢弃，不进行隧道分片重组。
退网、节点完全不可达或身份换钥会清理相应记录。LAN 新发起且不能匹配请求的包不会进入端到端隧道。

平台边界：Linux 使用 iproute2+nftables；已有防火墙的后续 drop 仍然生效，程序不覆盖宿主策略。
旧 Linux 内核不提供 IPv6 force_forwarding 时，IPv6 出口要求管理员预先启用 IPv6 forwarding。
Windows 使用 IP Helper 路由/转发及 IPv4 WinNAT；已有其他 WinNAT 实例时拒绝自动创建。
macOS 使用 utun 路由、系统转发及 PF 私有 anchor，SNAT 要求主规则已有 com.apple/* nat-anchor 引用。
Android 使用 VpnService 更新导入路由，不能发布内网。Windows/Android 导入内网时，同一地址族只能有一个活动 tunnel 地址，
避免系统选错源地址；Linux 路由显式设置 src，macOS 路由设置 -ifa。
转发设置会在正常退出时恢复；当前不支持同一主机/网络命名空间的多个出口进程共享同一物理接口并独立管理转发开关。
部分发布被撤回时对应规则立即移除，曾使用的物理出接口转发开关保留到全部出口撤回或进程正常停止时恢复。
强制杀进程/崩溃不保证清除系统 NAT 规则，应优先正常断开；macOS/Android 仍需目标平台实机验证。

## 邻接失效与路径撤回

UDP模式要求TCP控制与UDP数据均可达；TCP模式的控制和数据共用TCP，不检查UDP可达性。
TCP关闭、错误或控制保活超时，以及所选数据通道双向探测超时，均撤回邻接并退出可用下一跳集合。
不能仅用“没有业务数据”判断数据通道不通，也不能只用一次发送成功证明双向可达。
探测报文通过相邻会话认证：默认每5秒发送TCP保活及数据随机令牌挑战，后者走协商的UDP或TCP数据帧。
20秒没有TCP活动或合法数据探测回应则断开；初始握手最多10秒，重连按1、2、4、8秒退避。
协议定时器每 50 毫秒运行；每小时重新建立链路和端到端会话，身份密钥不变。
每个方向在累计发送 2^32 条 AEAD 记录前必须换会话，禁止回绕后复用 nonce。

失效处理撤销该邻接提供的候选路径及公钥引用，重算受影响节点的 ECMP 和 RPF 选择，
并向其他 peer 发布变化；通过其他健康邻接仍然可达的节点及其公钥继续保留。
例如 A 到 D 有 A-B-D 和 A-C-D，A-B 断开后只撤销前者，保留经 C 的路径和 D 的公钥。
失效按邻接依赖处理，不按路径字符串是否出现 B 处理：
若 C 仍通告有效的 A-C-B-D 路径，A 仍可使用它；B 自身也可能经 C 继续可达。

失效的直连会话退出可用状态并按重连流程恢复；只有 TCP 认证和所选数据通道双向可达都通过，
才重新进入 ESTABLISHED 并发布可用路径。目标节点全部路径消失时撤回其可达状态及公钥。

## 广播与组播

允许在同一虚拟网络内跨节点泛洪，中转节点也必须加入该虚拟网络。
第一版采用反向路径检查（RPF）结合隧道跳数限制，参考 PIM 按源构建转发树的思路：
https://www.rfc-editor.org/rfc/rfc3973.html#section-4.2
https://www.rfc-editor.org/rfc/rfc7761.html#section-4.2
本项目复用已有的节点可达表，把每个已认证 peer 视为一条逻辑点到点链路。
这里只借鉴 RPF 检查，并将它用于隧道内广播和组播，不实现完整 PIM 协议。
第一版仍向同网络成员泛洪，不增加组播 Join/Prune、RP 或组成员订阅协议。

RPF 的判定规则：
根据转发头的源节点身份，查询本虚拟网络中到该源节点的最短有效下一跳集合，
从中按稳定规则选出唯一的 RPF 上游 peer，不沿用单播按流选择多个下一跳的接收规则。
仅当报文来自这个 peer 时才接受并允许转发：

```text
expected_peer = select_rpf_peer(tunnel, header.source_node)
accept = expected_peer 存在 && incoming_peer == expected_peer
```

header.source_node 是最初注入该包的节点公布地址，中转时保持不变，不是外层 UDP 源地址。
根据已学习的节点信息把该身份与源 tunnel IP 绑定。
广播和组播当前解开逐跳保护后可以读取原始 IP 包，还需核对其源 IP 与源节点映射一致。
incoming_peer 是通过会话认证确定的入站 peer；由于多个 peer 共用 UDP fd，
不能用接收 fd 是否相同来代替 peer 检查。
每个虚拟网络中的源 IP 必须唯一对应一个节点，且该源节点的可达信息已被学习。
单播 ECMP 不意味着广播和组播同时接受多个上游；对同一个源仍只选定一个 RPF 上游 peer。
选路更新和报文处理在同一个线程内串行完成。
没有到源的有效下一跳时丢弃数据包，不能临时接受任意 peer 的包。
RPF 数据检查不用于阻止控制协议学习此前未知的节点可达信息。

本机 TUN 读出的广播和组播：
校验源 IP 属于本机在对应虚拟网络中的地址，设置初始 hop_limit，
通过该虚拟网络内已建立且获准承载此网络的各个 peer 分别加密发送。

从 peer 接收的广播和组播：
1. 验证并解密入站报文，检查会话防重放、虚拟网络成员关系和字段有效性。
2. hop_limit 为 0 时丢弃；如果源节点是本机，或源 IP 是本机在该网络的地址，也丢弃，避免接收绕回的本机包。
3. 查询源节点对应的唯一 RPF 上游，入站 peer 不匹配或源不可达时丢弃。
4. 通过检查后可投递到本机 TUN；hop_limit 为 1 时停止转发。
5. hop_limit 大于 1 时减 1，向同网络其他有效 peer 分别加密转发，排除入站 peer。

这里只限制接收方向；节点不必提前知道哪些邻居把自己选作 RPF 上游。
因此仍向除入站 peer 外的同网络邻居发送，由邻居执行自己的 RPF 检查。
例如 A-B-D 与 A-C-D 两条路径同时送来 A 的广播，若 D 到 A 的下一跳选定 B，
则 D 接受 B 的副本，丢弃 C 的副本。

在源可达信息收敛、下一跳无环、peer 数据通道双向可用且源只注入一次的条件下，
选定的 RPF 上游形成以源为根的转发树，避免多条路径的副本同时被接收。
第一版省去广播专用的源启动标识、全局包序号和跨 peer 去重缓存。
RPF 不提供“任何情况下每个包最多投递一次”的保证：
路由切换期间可能先后接受旧、新上游送来的同一个包，收敛期间也可能短暂丢包或出现转发环路。
本方案允许这些过渡期现象，保留 hop_limit 限制单个包的转发次数。
同一会话的重放报文仍由加密会话的序号和防重放窗口处理，这与跨路径全局去重不同。
如果以后需要跨路径严格去重，再增加源包标识和有期限的去重状态。

节点可达信息的通告、撤回、选路和断线收敛仍由已有的 TCP 控制协议负责。
UDP 隧道已定义虚拟网络、会话标识、链路加密序号、hop_limit 等封装字段，见 protocol.h/.cpp；
RPF 省去的是独立的广播去重机制和新增的组播控制协议，不会省去隧道自身的协议。
hop_limit 位于隧道封装头中，不把原始 IP TTL 改写成固定值，
也不要求它等于“初始值减去到源节点的跳数”。
初始 hop_limit 为 32；内层 IPv4 TTL / IPv6 Hop Limit 保持原值，虚拟网段视作同一逻辑链路。
组播按源虚拟网络泛洪，不实现组成员订阅或额外的组播作用域裁剪；
未配置的 IPv6 link-local 源地址不会通过源地址校验，不能把此模式视作完整的以太网邻居发现代理。

## MTU

只采用静态 MTU 预留封装空间，不实现 PMTU 自动探测、隧道分片/重组或自动 MTU 协商。
tun_mtu 为唯一 TUN 设备的 MTU，默认 1280；transport_mtu 为部署者配置的外层路径
MTU 下限，默认 1500，必须覆盖所有可能使用的路径（包括 ECMP 备选和广播/组播出口）。
该值是部署前提，不是程序探测所得；路径实际更小时由部署者下调配置。

必须满足 tun_mtu + 最大隧道及两层加密开销 + 外层 IP/UDP 头 <= transport_mtu。
逐跳保护在中转时替换，不按中转次数累加。超限报文直接丢弃并计数，不进入发送队列。
封装长度由线协议常量及实际序列化长度确定，不使用假设的固定余量代替计算。
当前 v1 记录头为 32 字节，GCM 标签 16 字节，转发头为 70 字节；单播两层保护共增加
166 字节。外层 IPv4 的 IP/UDP 头为 28 字节，IPv6 为 48 字节（不启用额外选项/扩展头）。
因此 transport_mtu=1500 时，IPv4 外层最多容纳 1306 字节的内层 IP 包，IPv6 外层为 1286。
默认 tun_mtu=1280 在两种外层下均满足这个静态预算。未来协议字段变动必须同步更新长度校验。
支持内层 IPv6 的虚拟网络要求 tun_mtu >= 1280；第一版不启用 TUN GSO/TSO 等大包卸载。
Android 创建接口时通过 VpnService.Builder.setMtu(tun_mtu) 设置同一上限。
TCP数据封装沿用这组保守的内层MTU校验，使混合中转和切回UDP不需改变TUN；不提供TCP专用大MTU。
外层TCP由系统按流分段，TLS和帧头不要求与内层包放在同一个TCP段中；没有新增应用层分片协议。

## 跨平台适配

网络协议和配置语义保持一致，按 Linux、Windows、macOS 和 Android 的后端组织实现。
设备创建、地址与系统路由配置、socket 句柄、事件通知和资源释放封装在平台层。
所有平台都保持一个逻辑 TUN 设备和一个公共 UDP socket 的基础结构，
不把多 socket 同端口绑定或 Linux 的 SO_REUSEPORT 作为运行前提。
当前 socket 基础实现一次选择 IPv4 或 IPv6 外层，所有 peer 与本机公布/绑定地址使用同一地址族；
IPv6 地址端口写为 [2001:db8::1]:65535。不启用双栈映射地址，内层虚拟网络可同时包含 IPv4 和 IPv6。

Linux 的设备后端可使用 /dev/net/tun：
https://kernel.org/doc/html/latest/networking/tuntap.html
Windows 的三层设备后端可使用 Wintun：
https://www.wintun.net/
macOS 可使用 utun 设备接口：
https://github.com/apple/darwin-xnu/blob/main/bsd/net/if_utun.h
Android 使用普通应用中的 VpnService 创建三层虚拟网络接口，不要求 root 权限：
https://developer.android.com/develop/connectivity/vpn

TUN 设备的读写和完成通知使用统一接口适配，不假设所有平台的 TUN 句柄都能按 POSIX fd
直接交给 libevent。平台设备后端在唯一的协议线程内驱动读写，不新增协议 worker。
Android 的系统回调只发出生命周期通知，由协议线程执行实际状态变更。
构建系统需要提供各平台的 libevent、OpenSSL 和设备后端依赖查找方式，
不能把当前依赖 pkg-config 的构建文件视为已经完成跨平台适配。

### Android 后端

Android 宿主应用负责配置导入、启动/停止、系统 VPN 授权和服务生命周期。
通过 VpnService.prepare() 发起所需的系统授权，按目标 Android 版本的要求配置并运行前台服务。
通过 VpnService.Builder.addAddress() 添加各虚拟网络的本机 tunnel_ip，
通过 addRoute() 把配置中的虚拟网段导入 TUN，最后调用 establish() 获取接口描述符。
默认只接管配置的虚拟网段，不因启用 Android 后端而自动添加全局默认路由。
https://developer.android.com/reference/android/net/VpnService.Builder

协议、加密、ECMP、RPF 和 peer 状态继续由共享 C++ 核心实现，通过 NDK 构建并经 JNI 接入。
TUN 描述符由 Android 平台层取得后交给原生核心，明确描述符所有权和关闭时机。
Android 核心不直接打开 /dev/net/tun，也不使用桌面平台的系统命令配置网卡。
https://developer.android.com/ndk/guides

每个 TCP 控制 socket 和进程唯一的公共 UDP socket 都必须经 VpnService.protect(fd) 处理，
使隧道传输走底层网络，避免其流量再次进入自己的 TUN；新建的重连 socket 同样处理。
protect 失败时不得把对应连接标记为可用。公共 UDP socket 使用 sendto/sendmsg 等按目的地址
发送的方式服务多个 peer，不把它永久 connect 到某一个 peer。
https://developer.android.com/reference/android/net/VpnService#protect(int)

处理 VPN 授权撤销、服务停止、底层网络丢失以及 Wi-Fi/蜂窝网络切换事件，
按既有失效规则撤回受影响邻接并重连，停止时在协议线程内关闭 socket 和 TUN。
同一进程中的网络切换不重新生成节点身份密钥；进程被系统终止后重新启动，则按初始化规则生成新密钥。

Android 仍使用相同的公布地址和节点身份规则，公布地址改变时按节点身份改变处理。
平台适配本身不解决移动网络的 NAT 入站可达性；若无法提供可达的公布 TCP/UDP 端点，
还需另行设计出站接入的端点学习、NAT 穿透或中继，不能假定仅启用 VpnService 就能满足这一条件。
Android 工程最低 API 26、目标 SDK 36，支持 arm64-v8a/x86_64，使用用户启动的 specialUse 前台服务。
配置保存在应用私有目录；点击连接时固定本次启动快照，授权期间的新保存不改变此次连接。
JNI 使用标准 UTF-8 字节传递，保持 PSK 与桌面端一致。
同进程重建服务复用进程身份密钥；停止和网络变化通过管道提交给唯一协议线程处理。

## 跨平台界面

Windows、Linux、macOS 使用 pywebview 原生窗口，Android 使用系统 WebView。
四平台共用离线 HTML/CSS/JS，默认提供本机地址、虚拟 IP/前缀、对端和网络授权表单。
密钥可由 OpenSSL 生成 32 字节随机数，以 64 位十六进制文本配置；同一对节点共用该密钥。
高级设置包含入站开关、入站网段限制、本地绑定、MTU 和 JSON 编辑。
JSON 修改必须显式应用到表单，校验失败保留原文；未应用时不能用旧表单悄悄保存或连接。
新增网络保留已有 peer 的选中范围，删除网络不能把空权限列表退化成全部允许。
继续提供配置导入/校验/保存、连接状态和日志。
桌面宿主通过独立后台进程、私有状态文件及 stdin 控制核心，不开放公网管理端口。
界面与后台使用仅绑定127.0.0.1随机端口的本机IPC，双向HMAC挑战验证私有状态目录中的随机凭据；不是HTTP服务。
开启远控且无人值守时，关窗保留后台；其他情况关窗停止核心。显式断开始终停止后台及核心。
后台异常退出产生的 stdin EOF 同样触发核心正常停止；重新打开相同配置目录可以接回仍运行的后台。
Android 通过 VpnService/JNI 驱动核心，Activity 关闭不停止已连接 VPN。
状态快照只在协议线程生成；界面线程不能直接调用 Node 的状态变更方法。
界面/浏览器/日志宿主可以有线程，用户态协议核心继续单线程；每实例一个公共 UDP socket，所属位置由设备后端决定。
运行中支持配置热加载；界面保存、命令行应用均先由原生核心校验，再在唯一协议线程执行。
未变化配置不重建资源；仅远控策略变化即时应用。Peer地址、PSK或网络授权变化只撤回和重建受影响邻接，未变化邻接保留。
公布/绑定地址、监听、虚拟网络、MTU、地址服务、发布网段/SNAT等变更在原进程内重建网络资源，保持进程身份密钥；会中断现有连接并重新认证。
重建先释放旧UDP/TUN再创建新资源，保持单UDP socket及单TUN约束。校验失败不改变运行配置；应用失败尝试恢复旧资源，恢复失败明确报告并保留可再次应用的管理入口。
桌面GUI和命令行共用认证本机IPC与配置事务：文件先暂存，运行应用成功再提交；保存失败回滚运行配置。配置目录锁和文件SHA256版本检查防止并发覆盖。
命令行配置工具支持查看（默认隐藏PSK）、完整JSON导入、JSON Pointer字段设置、Peer/静态网络增删、启动/停止/状态及reload；不需要打开GUI。
直接运行C++核心可使用--watch-config监视配置文件；POSIX的SIGHUP请求重载。父进程管理的stdio模式只通过config_apply应用，避免与桌面策略不同步。
“运行中”仅表示核心已启动，peer 是否建立连接以双通道认证后的邻居状态为准。
桌面桥接验证初始页面令牌；Android 仅允许受限本地资源，禁止外部导航和网络加载。

## 远程桌面

已实现独立Python远控后台、共享界面及Windows、Linux X11、macOS的采集/输入后端。
Windows真实截图、Linux隔离X11桌面的端到端屏幕/键鼠已验证；macOS实现尚无目标平台实测。
本版提供已登录桌面的屏幕查看和鼠标键盘操作，支持预授权后无人值守；不支持Wayland、登录界面或安全桌面。
macOS需要初次授予屏幕录制、辅助功能权限。Android本版仅隧道访问，不提供远控控制端/被控端。
开启远控且无人值守时关窗保留后台；后台在当前用户图形会话中运行，不自动安装开机系统服务。
采集、编码和输入处理放在独立组件中，隧道协议核心仍保持单线程。

被控端提供两种访问模式：
- authorized_devices（默认）：仅已授权设备，按保存的设备公钥和查看/键鼠权限决定是否允许连接。
- all_tunnel_nodes：允许所选虚拟网络内所有有效节点查看屏幕和操作键鼠，无需逐台加入授权名单。

“谁都可以控制”指所选 tunnel 的所有有效成员，包括经其他节点中转到达的成员；不向公网匿名开放，
也不包括仅通过发布内网接入的普通设备。多网络时必须明确选择开放的 tunnel，不因新增网络扩大权限。
两种模式都需验证连接所属的有效节点与网络，并保留远控连接的认证加密；不能仅凭源 IP 属于虚拟网段放行。
远控组件通过私有stdin/stdout RPC从核心取得可验证的连接、节点、网络绑定，不接受对方自报身份作为成员证明。
核心remote_sign/remote_verify用现有进程Ed25519身份签署/验证用途、网段、节点、源IP和握手载荷，
并核对当前活动网络、有效路径及最新公钥。载荷绑定双方随机数、TLS证书、长期设备公钥、IP和请求权限。
桌面TCP连接使用Python ssl/OpenSSL TLS1.3；控制端首先确认并保存被控端长期设备公钥。
服务只绑定所选tunnel的本机虚拟IP，默认端口47831，可配置；不会绑定通配地址或公布公网IP。
受管网络资格失效、本机退出对应网络或连接不再具备有效成员绑定时，终止依赖该网络的远控会话。

设备授权使用独立、长期保存的公私钥，不复用每次进程启动重新生成的隧道身份密钥。
被控端保存获准控制端的公钥、名称与权限，控制端也固定被控设备身份；地址变化或正常重启不重置授权。
密钥丢失或重置后重新授权，普通路径公钥更新不得覆盖已保存的远控设备身份。
all_tunnel_nodes 模式不要求预存控制端公钥，但仍验证有效成员及其当前会话身份。

unattended 控制是否省略每次现场确认：true 时，通过当前访问策略的连接可直接进入；false 时仍需本机同意。
因此 all_tunnel_nodes 与 unattended:true 组合表示所选虚拟网络成员均可无人值守控制。
全员模式下删除某设备的授权名单记录不会阻止它继续连接；需要限制到指定设备时切回 authorized_devices。
策略热更新会断开入站会话并按新策略重连；名单撤销立即终止该设备在名单模式下的会话。
撤销在锁内先标记失效，已接收但尚未执行的输入批次也不能继续执行；过期批准请求不能恢复已撤销授权。
关闭远控立即断开全部会话；断开或撤销输入权限时释放已按下的键和鼠标按钮。
首版同时只允许一个控制端，后来的连接显示忙碌，不自动抢占；本机界面提供当前连接与终止入口。

配置片段（完整配对示例见examples/desktop-host.json和desktop-client.json）：
```json
"remote_desktop": {
  "enabled": true,
  "networks": ["10.1.0.0/24"],
  "access": "all_tunnel_nodes",
  "unattended": true
}
```
enabled 默认 false，access 默认 authorized_devices，unattended 默认 false。
networks 只能引用本机已有的规范虚拟网段；单网络时可省略，多网络时必须显式指定，空列表不允许。
关闭服务且尚未选择网络时可以暂时为空；规范化后显式保留选择，避免新增网段扩大权限。
可选port默认47831；device_name为空时取系统名称，最多128 UTF-8字节且不含ASCII控制字符。
界面提供远控开关、开放网络、“仅已授权设备/本虚拟网络内所有节点”单选、无人值守开关与授权设备管理。
保存、导入、旧配置迁移均不得自动开启远控、全员模式或无人值守。

单屏JPEG最大1600×900、最多8帧/秒，每次只传一帧，有界输入队列合并连续移动，溢出释放按键。
长期设备身份和授权库分别保存在desktop-identity.pem、desktop-devices.json；已有文件损坏报错，不覆盖生成。
同目录仅允许一个后台实例；文件通过临时文件和原子替换保存。桌面IPC与核心RPC均有长度和并发上限。
直接启动C++ tunnel不启动屏幕组件；使用GUI或python -m remote_desktop.daemon启动完整后台。
使用方式、系统权限和测试命令见remote_desktop/README.md。

## Peer 状态

```cpp
enum PeerState {
    PEER_STATE_INIT,          // 初始化
    PEER_STATE_CONNECTING,    // TCP 连接中
    PEER_STATE_VERIFICATING,  // 认证与密钥协商中
    PEER_STATE_ESTABLISHED    // TCP 已认证且所选数据通道双向可达
};
```

TCP控制或所选数据通道失效时退出ESTABLISHED，执行邻接失效与路径撤回规则，
然后按退避策略进入重新连接、认证和数据通道探测流程。
重连只重建会话，不重新生成本次进程的节点身份公私钥。
